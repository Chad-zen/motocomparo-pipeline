## The incident

`enrich` re-categorised 1,764 offers to `helmet.modular`. `match` was then run
**without `--reset`**, so it only processed new offers and never re-evaluated
existing products. One product (133904) ended up holding offers in category 2 and
category 4 at once. `verify` caught it and refused to continue.

The CLI had printed `now run mcpipe match --reset to apply` immediately before.
The instruction was there and was not followed. `match --reset` then rebuilt
everything consistently and `verify` returned 0.

## Debts found tonight, not fixed

1. `raw_offer_title_trgm` — GIN index on `raw_title`, **used by no query in the
   codebase**, built for the fuzzy stage that was never written. Maintained on
   every upsert of 767k rows.
2. `size_code = 'NOIR'` on 6,948 signatures — a colour parsed into the size field.
3. `freshness` cannot see stale input: `raw_offer.last_seen` is stamped when
   `normalize` runs, not when the feed was downloaded. Re-processing a 3-day-old
   file marks every offer fresh. The 24-hour guard is defeated by exactly the
   case it exists for.
4. `textnorm.size_code` files 35-52 as EU and 53-65 as CM, so a jacket in EU 54
   becomes "54 cm" like a helmet's head circumference.
5. `normalize` + `signature` are ~510s of pure single-core Python, independent
   per merchant. Parallelising them halves the wall clock.
